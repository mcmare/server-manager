# Server Manager v1.1 — итоговая самопроверка

Дата: 2026-11-07.

Независимое ревью: **НЕ проводилось**. В данной сессии нет инструмента запуска отдельного субагента/ревьюера. Документ содержит только локальную проверку автора, которая не является заменой независимого ревью.

## Реализовано и проверено unit-тестами

- Инъецируемый argv runner, таймаут и запрещённый shell.
- Состояние и журнал с записью 0600 и редактированием секретных ключей.
- Сводка слушающих портов TCP/UDP, включая IPv6 и неизвестных владельцев.
- Обзор конфигураций sites-available/sites-enabled с маркировкой опасных symlink.
- Генератор HTTP reverse-proxy с валидацией домена/адреса/порта.
- Транзакции включения/отключения/создания сайта, nginx -t, reload, rollback и persistent backup.
- Ручное восстановление Nginx backup с проверкой изменённых файлов.
- Управление существующими службами systemd и создание безопасно именованных units.
- Обнаружение Compose из меток контейнеров, stop/up, снимки restart policy.
- Выборочная очистка Compose: явные подтверждения, защита томов и mounts, отказ при изменении контейнера, проверка writable layer, без глобальных prune.
- Проверка кандидатов images по manifest и по фактическим ссылкам контейнеров.
- Certbot как отдельная операция, Nginx test и backup.
- Интерактивное меню и неинтерактивные `ports`, `sites list`, `--dry-run`.

## Выявленные ограничения для независимого ревью

1. Не выполнялось тестирование на реальной изолированной Debian VM с nginx, docker, systemd и certbot; unit-тесты используют заглушки.
2. Systemd↔порт в автоматическом выключении сайта не реализован: при неизвестном владельце безопасный отказ. В меню systemd действия доступны отдельно.
3. Сложные Nginx конфигурации нельзя считать полностью разобранными. Управление symlink ограничено; подтверждения не гарантируют, что другой включённый файл ссылается на те же ресурсы.
4. Docker Compose с несколькими конфигурационными файлами блокируется; необратимые операции требуют отдельного подтверждения.
5. Невозможно полностью доказать сохранность данных в произвольном writable layer. Применена проверка `docker diff` и известных критичных путей, плюс обязательное подтверждение оператора; остаточный риск остаётся.
6. Регистровый manifest показывает доступность ссылки сейчас, но тег может переехать. Автоматическое восстановление images и повторная сборка не тестировались.
7. Не выполнялись проверки на race conditions между финальной инвентаризацией и фактическим вызовом Docker; демон Docker должен отказать в удалении используемого image, но риск пересоздания контейнеров внешним оркестратором сохраняется.
8. Certbot может модифицировать несколько файлов; автоматический откат побочных изменений Certbot не реализован.
9. Поддержка restart policy после Compose recreate ограничена runtime-контейнерами; нет автоматического восстановления при смене container ID.
10. Текущий код не предназначен для запуска без тестирования на целевой среде.

## Для внешнего проверяющего

Проверить: пути и symlink TOCTOU, точность привязки backend, Docker тома и writable layer, реальную совместимость `docker compose` команд, поведение Certbot на SSL-виртуальных хостах, root-only ACL для журнала/backup и ошибочные пути исполнения. После независимого ревью — прогон на disposable Debian VM.
