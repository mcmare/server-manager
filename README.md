# Server Manager v1.1 (предварительная реализация)

Локальная утилита для Debian: управление виртуальными хостами Nginx, службами systemd, существующими Docker Compose-проектами, Certbot и занятыми портами.

> **Статус: тестовая версия.** Код прошёл локальные изолированные unit-тесты, но **не** проверен независимым агентом или на тестовой Debian VM с установленными Nginx, Docker и Certbot. Использовать на рабочем сервере только после отдельной проверки и резервного копирования. 

## Быстрый запуск — интерактивное меню

Распакуйте архив, перейдите в каталог проекта и запустите **без аргументов**:

```bash
cd server-manager
sudo python3 server-manager.py
```

Появится главное меню с нумерованными разделами. Выбирайте нужный раздел, вводя его номер. Для выхода — `0`. Внутри разделов можно выбирать сайты и службы по номеру. Изменяющие операции запрашивают отдельное подтверждение `ДА`.

Для ознакомления без изменений на сервере:

```bash
python3 server-manager.py --dry-run
```

Если пакет установлен через `pip`, команда `sudo server-manager` также открывает интерактивное меню. Аргументы `ports` и `sites list` оставлены как необязательные команды для автоматизации.

## Установка зависимостей

Требуется Debian, Python 3.10+, `nginx`, `systemctl`, `ss`; Docker и Certbot нужны для соответствующих пунктов меню.

```bash
sudo apt update
sudo apt install python3 python3-venv python3-setuptools iproute2 nginx
python3 -m venv .venv
.venv/bin/python -m pip install --no-build-isolation -e .
sudo .venv/bin/python -m server_manager
```

Если `pip` сообщает об отсутствии инструментов сборки, установите системные `python3-pip`, `python3-setuptools`, `python3-wheel`, либо используйте запуск `sudo python3 server-manager.py` без установки пакета.

## Меню

```text
1  Сайты Nginx — список
2  Добавить HTTP reverse-proxy сайт
3  Отключить сайт и при необходимости Compose backend
4  Включить сайт
5  systemd: старт/стоп/enable/disable или новый unit
6  Docker Compose: сервисы, restart=no, опциональная очистка
7  Certbot: список/выпуск/renew dry-run
8  Компактный просмотр портов
9  nginx -t
10 Журнал и восстановление резервной копии Nginx
0  Выход
```

### Защита данных

- Nginx управляется **только** через `/etc/nginx/sites-available` и `/etc/nginx/sites-enabled`. Сложные или внешние symlink-конфигурации не изменяются. Перед каждой операцией сохраняется snapshot в `/var/lib/server-manager/backups` (0600), после неё выполняются `nginx -t` и `systemctl reload nginx`; ошибки вызывают автоматический откат ссылок/созданных файлов.
- Включение/отключение существующего сайта не редактирует его конфигурацию. Certbot запускается отдельно.
- Новые systemd-службы создаются только с именем `server-manager-<имя>.service`, без перезаписи существующих файлов, с непривилегированным пользователем.
- Docker Compose **не** редактирует YAML. Обнаруживается по меткам контейнеров. Изменение restart через `docker update` не гарантирует сохранение политики после пересоздания контейнера.
- Очистка Docker требует отдельного подтверждения и применяется только к целому выбранному Compose-проекту; сохраняет все bind mounts и Docker volumes. Анонимные тома блокируют очистку. Данные в writable layer контейнера **удаляются** вместе с контейнером: перед операцией оператор должен убедиться, что важные данные находятся во внешних mounts. Не используются `down -v`, глобальный `prune`, `image rm -f`.
- Образы удаляются исключительно если больше не используются контейнерами, имеют ровно один тег и доступный удалённый Docker manifest; в прочих случаях остаются на диске. Проверка manifest не гарантирует, что удалённый тег всегда будет указывать на тот же образ в будущем.
- Не проверенные backend-владельцы не останавливаются автоматически.

### Известные ограничения

- Нет гарантии правильного сопоставления systemd-сервиса с портом: сервис можно выбрать и управлять им в меню, но после отключения Nginx автоматическая остановка доступна только для однозначно опознанного Docker Compose endpoint.
- Скрипт не создаёт Docker Compose проекты и не восстанавливает контейнерные политики при их пересоздании.
- Создание сайта поддерживает обычный HTTP reverse-proxy. WebSocket/upstream/нестандартный конфиг надо настраивать отдельно.
- Обнаружение Compose-проекта с несколькими файлами (`-f file1 -f file2`) блокируется для автоматического управления.
- Для тестов используются заглушки системных команд: реальное поведение на конкретном Debian нужно проверять отдельно.
- Успешный `certbot` может переписать конфигурацию сайта. Резервная копия создаётся, но автоматический rollback изменений Certbot в этой версии не реализован.
- Ручное восстановление Nginx backup доступно в меню 10. Оно отказывается перезаписывать изменённый после резервирования конфигурационный файл.
- Автоматическое определение владельца порта systemd и предварительная гарантированная проверка сохраняемости writable layer не реализованы; уничтожать контейнеры следует только после своей проверки данных.

## Тесты

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q server_manager
```

Тесты не вызывают реальный `docker rm`, `nginx reload`, `systemctl stop` или `certbot`.
